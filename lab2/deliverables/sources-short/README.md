# Лабораторная 2 Включение и агрегирование ACOM

Автор: Фирсова Валерия Дмитриевна. Группа: 24ТИДИ.
Вариант эксперимента: short; три независимых повтора.

Реализацию обоих объектов в `variants/repeat-N/Reuse.c` сгенерировала локальная
Qwen2.5-Coder-14B-Instruct-4bit через обёртку ARPO. Численные методы Bucket sort
побайтно взяты из первой работы. Общие фабрики и независимые клиенты подготовил
организатор; исходники калькуляторов преподавателя сохранены без редактирования.

## Сборка и проверка

Нужны macOS Apple Silicon, Apple Command Line Tools (`clang`, `ar`, `nm`, `xcrun`)
и Python 3. Внешние Python пакеты, MLX, веса и окружение солвера для сборки не нужны.
Отдельно получите у преподавателя Eco.Framework из Eco.Framework_20260918.zip.
Архив не содержит частные файлы Eco SDK. Хеши требуемых файлов проверяются по receipt.

```sh
python3 build.py --sdk "/absolute/path/Eco.Framework" --repeat 1 --profile A
python3 build.py --sdk "/absolute/path/Eco.Framework" --repeat 1 --profile A --check
python3 build.py --sdk "/absolute/path/Eco.Framework" --repeat 1 --profile C --check
```

Аналогично выполните повторы 2 и 3. Профили A и C раздельны, поскольку в исходной
учебной поставке у них совпадает CID. Оба профиля также используют B, D и E.
`--check` собирает доверенный `checks/acom.c` с UBSan и выполняет матрицы QI,
identity, lifetime, настоящий реестр, внешний controller, отказы, делегирование
арифметики и регрессию сортировки. Это те же C проверки, что применялись в серии.
Локальные пути инструментов формируются заново; SDK и исходники сверяются по SHA256.
Сохранённые метаданные исходного эксперимента не переписываются под новый компьютер.

```sh
python3 build.py --sdk "/absolute/path/Eco.Framework" --repeat 1 --profile A --benchmark calls
python3 build.py --sdk "/absolute/path/Eco.Framework" --repeat 1 --profile A --benchmark sort
```

Результат находится в `.build/repeat-N-PROFILE/BuildFiles/Standalone`.
В `builds/macos-arm64` приложены статические архивы компонента и учебных калькуляторов.
Они не содержат приватные статические библиотеки SDK; для конечной линковки нужен SDK.
Клиент входит через EcoMain, стандартную main предоставляет Eco.System1.

## Состав

- `common` — ABI, контракт, численные методы, фабрики, Vendor и демонстрационный UnitTest.
- `variants` — три точных итоговых файла Qwen; ни один организатором не дописывался.
- `checks` — доверенный полный UnitTest и два независимых измерительных клиента.
- `prompts` — исходные промпты и постановка; ТЗ соответствует структуре ГОСТ 19.201-78.
- `provenance` — происхождение зависимостей, контрольные суммы и реальные накопленные метрики.
- `source-manifest.json` — целостность комплекта без генерируемой `.build`.

Полные HTTP журналы, неудачные ответы, уточнения и архивы контекста сохранены у
организатора в каталоге исходного эксперимента. Единый отчёт Word и CSV измерений выдаются
рядом с архивами исходников. Тариф локальных запросов равен нулю, энергия не измерялась.
Проверки конечны и не доказывают корректность всех входов или старых внутренностей SDK.
Нет проверки многопоточности, межпроцессной маршализации и всех отказов внутри Vendor.
Не распространяйте отдельно полученный SDK и веса как часть публичного репозитория.
